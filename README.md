# Your blog, ready to upload

Everything in this folder is a complete GitHub Pages blog. Upload the CONTENTS of this folder
(not the folder itself) to a repo named `ZacheryCao.github.io`.

Do not upload this README.md. It is instructions for you, not part of the site.
(`_config.yml` already excludes it from the build, so uploading it by accident is harmless.)

## What each file does

```
_config.yml                  site settings: title, email, URL style
index.md                     HOME PAGE. Lists every post automatically.
archive.md                   "All posts" page, grouped by year.
about.md                     About page.
_layouts/default.html        shared frame: top navigation + footer, wraps every page
_layouts/post.html           article frame: title, date, tags, back-link
assets/style.css             all styling
_posts/2026-11-21-...md      your first article
```

The navigation (Home / All posts / About) lives in `_layouts/default.html`, so it appears on
every page. The home page list is generated by a loop over `site.posts`, so you never edit
`index.md` to add a post.

## Upload steps

1. Go to https://github.com/new
   - Repository name: `ZacheryCao.github.io`  (exact format, required for a personal site)
   - Public
   - Check "Add a README file"
   - Create repository

2. In the new repo: **Add file -> Upload files**.
   Drag in everything from this folder EXCEPT README.md.
   Important: drag the items so that `_config.yml`, `index.md`, `_layouts`, `_posts`, `assets`
   land at the TOP LEVEL of the repo, not inside a subfolder.

   GitHub's web uploader keeps folder structure when you drag folders. If `_layouts` or
   `_posts` do not come through, create them by hand: on the repo page choose
   **Add file -> Create new file**, type `_posts/placeholder.md` as the name (the slash
   creates the folder), commit, then upload the real file into it and delete the placeholder.

3. Commit changes.

4. Repo **Settings -> Pages**
   - Source: Deploy from a branch
   - Branch: `main`, folder `/ (root)`
   - Save

5. Wait 1-2 minutes, then open https://zacherycao.github.io

## Adding your next post

Create one file in `_posts/` named `YYYY-MM-DD-some-title.md`:

```markdown
---
layout: post
title: "Your post title"
date: 2026-12-01
tags: [evaluation, agents]
summary: "One sentence shown under the title on the home page."
---

Body starts here. Use ## for section headings, not # (the layout renders the title).
```

That is the whole workflow. The home page, the archive, and the URL
(`/posts/some-title/`) all update on their own. The filename date must match the `date:` field.

## Notes

- The site builds with Jekyll, which GitHub Pages runs for you. Nothing to install locally.
- To preview before publishing, make the repo private first? No: Pages needs a public repo on
  the free plan. If you want a dry run, create a separate public repo named anything else and
  enable Pages there; it will serve at `zacherycao.github.io/<repo-name>/`.
- The article text is the de-identified version: no employer name, no product name, no
  business metrics. The About page and footer carry your name, degree, and email. Once
  indexed, search engines may keep copies even if you delete the repo later.
